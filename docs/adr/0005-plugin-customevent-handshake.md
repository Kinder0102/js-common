# 0005 插件握手用 CustomEvent

## 狀態

已接受。

## 背景

插件是獨立構建、獨立部署的一段 DOM 加腳本。宿主在運行時才需要發現它們，而雙方不能共享模塊實例：插件可能是另一個 bundle，甚至是別的團隊用別的框架寫的。

需要一個通道，滿足：不需要 import 對方、不需要約定的全局對象名、能容忍加載順序不一致。

## 決策

用兩個 `CustomEvent` 完成握手，事件名固定：

- `js-plugin:check`：宿主 → 插件
- `js-plugin:register`：插件 → 宿主

宿主按固定間隔重複派發 `check`，直到收到 `register` 或超時。之後通過 `broadcast` 單向派發業務消息。

## 理由

- `CustomEvent` 是 DOM 標準，任何框架都能監聽，不綁定模塊系統。
- 事件名是字符串常量，跨 bundle 的唯一共識就是一個字符串，耦合最小。
- 輪詢 `check` 允許插件腳本在宿主之後加載，解決順序問題。
- 不用全局單例（`window.__plugins`）：多實例頁面會打架，也容易泄漏。

## 後果

- 握手是**異步且可能失敗**的。`ready()` 在超時後仍 resolve，調用方不能把它當作就緒信號，見 [KNOWN-GAPS](../KNOWN-GAPS.md)。
- `check` 會重複到達，插件側必須冪等。
- 業務消息名需要自帶命名空間前綴，否則不同插件的同名消息會串。
- 沒有返回值通道，雙向通訊要各自再定義一對事件。
